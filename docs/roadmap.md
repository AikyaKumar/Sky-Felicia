# Roadmap

> **Status:** Suggested sequence, not a dated commitment. Adjust priorities to the hackathon timeline, team capacity, and platform. Each milestone should leave the team with a demonstrable result.

## 1. Align on the playable slice

- Choose the target platform and stack.
- Agree on one beginner-friendly mission, its science objective, pass condition, and a small set of constraints.
- Decide the initial collaboration mode and define the minimum accessibility baseline.
- Agree on how scoring explains outcomes.

**Done when:** The team can describe the first mission, its player journey, and its measurable pass criteria without unresolved core-scope choices.

## 2. Build the mission design loop

- Present the mission objective, requirements, and resource limits.
- Let a player choose from an initial set of launch, orbit, spacecraft, and payload options.
- Calculate and display the major tradeoffs, including mass, power, cost, and science capability where modeled.
- Validate the configuration and explain incompatibilities.

**Done when:** A player can create a design and understand whether it meets the selected mission's requirements.

## 3. Make one mission playable

- Run a mission using the selected design.
- Add the minimum operational decisions needed to demonstrate resource and spacecraft management.
- Include a small, intentional set of events if time allows.
- Show mission status using accessible cues.

**Done when:** A player can start, operate, and finish or fail one mission, and the outcome reflects the chosen design and decisions.

## 4. Close the learning and iteration loop

- Generate a report of objective outcomes, resource use, decisions, and failures.
- Explain why key results occurred.
- Save the design and allow it to be refined after the attempt.
- Add concise learning explanations and optional deeper information for core concepts.

**Done when:** A player can understand a result, revise a design, and try again.

## 5. Integrate and present the hackathon build

- Test the end-to-end player flow and resolve blocking issues.
- Verify that the demonstration works on the intended platform.
- Prepare a short walkthrough showing a design tradeoff, mission decision, and explanatory report.
- Clearly distinguish implemented features from planned ideas in the demo and repository.

**Done when:** The team can reliably demonstrate the intended playable slice and explain its educational value.

## Later opportunities

Consider only after the core loop is stable:

- More missions, destinations, orbits, and advanced components.
- More detailed launch-vehicle construction and simulation.
- Expanded emergency events and operational scenarios.
- Multiplayer improvements, progression rewards, or leaderboards.
- Adaptive difficulty and additional accessibility support.

## Suggested prioritization

When time is limited, prioritize in this order:

1. A clear objective and one complete mission loop.
2. Visible, understandable engineering tradeoffs.
3. An informative result report and design iteration.
4. Accessibility and beginner-friendly explanations throughout the experience.
5. Additional content, progression, and competitive features.

This order is a recommendation; the team should revisit it when the target platform and judging criteria are known.
